### 1.2 패키지 임포트 그래프

```
@gi-engine/core  ────────────────────────────────────────────────────┐
  (타입, 헬퍼, I18nManager, validatePuzzle, createInitialSaveState)   │
                                                                      ▼
@gi-engine/runtime ─── (IIFE 번들로 빌드됨) ──→  PreviewPane (iframe srcdoc 주입)
                                                                      ▲
@gi-engine/exporter ─── bundle() 함수 ────────────────────────────── │
  (브라우저 호환 번들 엔트리)                    ExportDialog.tsx      │
                                                                      │
packages/editor/src/ ────────────────────────────────────────────────┘
  (React 19 앱, Zustand 스토어, Radix UI, Tailwind CSS)
```

**의존성 규칙**:
- `packages/editor` → `@gi-engine/core`: 직접 import (타입 + 함수)
- `packages/editor` → `@gi-engine/exporter`: `bundle()` 함수만 import. exporter는 브라우저 환경에서 `Blob` 기반으로 동작하는 별도 빌드 엔트리(`browser` 필드)를 제공해야 한다.
- `packages/editor` → `@gi-engine/runtime`: 직접 import 없음. Vite 빌드 시 runtime IIFE를 정적 에셋으로 포함하고, `PreviewPane`이 `srcdoc` 문자열로 주입한다.

### 1.3 상태 관리: Zustand + Immer

에디터의 모든 상태는 단일 `EditorStore`에서 관리된다. 복잡한 중첩 업데이트는 Zustand의 `immer` 미들웨어로 처리한다.

```
EditorStore (Zustand + Immer)
├── definition: GameDefinition        ← 게임 데이터의 단일 진실 원천
├── projectMeta                       ← 파일 경로, dirty 여부
├── selection                         ← 선택된 엔티티 ID
├── ui                                ← 패널, 확대/축소, 프리뷰 상태
└── actions                           ← 모든 변이 함수
```

### 1.4 빌드: Vite 앱 모드

에디터는 라이브러리가 아닌 **단독 실행 가능한 정적 웹 앱**으로 빌드된다.
- `vite build` → `packages/editor/dist/` (HTML + 청크 JS + CSS)
- 라이브러리 모드(`lib`) 사용 안 함
- `index.html`이 Vite 진입점

### 3.2 Words 저장 위치

`Word` 목록은 `GameDefinition`의 최상위 필드가 아니라 사건(Case) 단위로 분산 관리해야 한다. 그러나 스펙 수락 기준 30번에서 "definition에 별도로 관리되는 `words` 배열"을 언급하고 있으므로, `GameDefinition`에 루트 레벨 `words: Word[]` 필드를 추가하는 것을 **core 타입 확장 제안**으로 명시한다.

**설계 결정**: `GameDefinition`이 `words: Word[]`를 포함하도록 `@gi-engine/core`의 `types.ts`를 확장하거나, 에디터 스토어에서 `definition.acts`를 순회해 `words`를 파생(derive)한다. Phase 4에서는 **루트 `words: Word[]` 필드 추가**를 권장한다.

## 5. 핵심 구현 세부사항

### 5.1 캔버스 좌표계

```typescript
// src/utils/coordinate.ts

/** 디자인 해상도 (씬 원본 좌표계) */
export const DESIGN_WIDTH = 1920;
export const DESIGN_HEIGHT = 1080;

/**
 * 캔버스 DOM 좌표 → 씬 원본 해상도 좌표 변환
 * canvasRect: getBoundingClientRect() 결과
 * sceneDimensions: scene.dimensions (또는 1920×1080 기본값)
 */
export function canvasToScene(
  canvasX: number,
  canvasY: number,
  canvasRect: DOMRect,
  sceneDimensions: { width: number; height: number }
): { x: number; y: number } {
  const scaleX = sceneDimensions.width / canvasRect.width;
  const scaleY = sceneDimensions.height / canvasRect.height;
  return {
    x: Math.round((canvasX - canvasRect.left) * scaleX),
    y: Math.round((canvasY - canvasRect.top) * scaleY),
  };
}

/**
 * 씬 원본 해상도 좌표 → 캔버스 CSS 픽셀 변환 (렌더링용)
 */
export function sceneToCanvas(
  sceneX: number,
  sceneY: number,
  canvasRect: DOMRect,
  sceneDimensions: { width: number; height: number }
): { x: number; y: number } {
  const scaleX = canvasRect.width / sceneDimensions.width;
  const scaleY = canvasRect.height / sceneDimensions.height;
  return { x: sceneX * scaleX, y: sceneY * scaleY };
}
```

캔버스는 `aspect-ratio: 16/9`를 유지하며 CSS `object-fit: contain`으로 에디터 중앙 패널에 맞춘다. `zoom` 상태는 CSS `transform: scale(zoom)`으로 적용하며, 좌표 변환 시 zoom factor를 canvasRect에서 자동으로 반영한다.


### 5.2 핫스팟 선택 — SVG 오버레이 클릭 감지

`HotspotOverlay`는 SVG로 구성된다. 각 핫스팟 rect는 `<rect>` 요소로 렌더링되며, `pointer-events: all`로 설정된다. 클릭 이벤트는 SVG 이벤트 버블링을 통해 오버레이 컨테이너로 전달된다.

### 5.3 드래그-to-리사이즈 핫스팟 — PointerEvent Capture

```typescript
// src/hooks/useCanvasDrag.ts
export function useCanvasDrag(svgRef: RefObject<SVGSVGElement>) {
  const [dragState, setDragState] = useState<DragState | null>(null);

  const handlePointerDown = (e: PointerEvent, hotspotId: string, handlePos: HandlePosition) => {
    e.currentTarget.setPointerCapture(e.pointerId);  // pointer capture
    setDragState({ hotspotId, handlePos, startX: e.clientX, startY: e.clientY, ... });
  };

  const handlePointerMove = (e: PointerEvent) => {
    if (!dragState) return;
    const dx = e.clientX - dragState.startX;
    const dy = e.clientY - dragState.startY;
    // svgRef의 viewBox를 통해 픽셀 → 씬 좌표 변환
    const sceneScale = computeSceneScale(svgRef.current!);
    const newArea = applyHandleDelta(dragState, dx * sceneScale, dy * sceneScale);
    setLocalArea(newArea);   // 로컬 상태만 업데이트 (스토어 미기록)
  };

  const handlePointerUp = () => {
    if (dragState && localArea) {
      store.updateHotspotArea(caseId, sceneId, dragState.hotspotId, localArea);
    }
    setDragState(null);
  };
  // ...
}
```

`setPointerCapture`를 사용하므로 포인터가 SVG 영역 밖으로 나가도 드래그가 유지된다.

### 5.4 에셋 업로드 — FileReader → base64 → AssetDefinition

```typescript
// src/components/shared/AssetUploader.tsx
const handleFileChange = (e: ChangeEvent<HTMLInputElement>) => {
  const file = e.target.files?.[0];
  if (!file) return;

  const reader = new FileReader();
  reader.onload = (ev) => {
    const dataUrl = ev.target?.result as string;   // data:image/png;base64,...
    const [header, base64] = dataUrl.split(',');
    const mimeType = header.match(/:(.*?);/)?.[1] ?? 'application/octet-stream';

    const asset: AssetDefinition = {
      id: generateId(),       // nanoid
      type: file.type.startsWith('image/') ? 'image' : 'audio',
      src: file.name,
      inline: base64,         // inline=true 패턴: base64 문자열 저장
      mimeType,
      size: file.size,
      alt: { ko: '', en: '' },
    };
    onUpload(asset);          // → store.addAsset(asset)
  };
  reader.readAsDataURL(file);
};
```

에디터 내 모든 에셋은 `AssetDefinition.inline`에 base64로 저장된다. 이를 통해 `.gi-project` 파일이 단일 JSON으로 완결되며, exporter는 `inline` 필드를 그대로 사용해 HTML에 data URI로 삽입한다.

### 10.2 런타임 IIFE를 PreviewPane에 주입하는 방법

`@gi-engine/runtime`은 에디터의 npm 의존성으로 선언하지 않는다. 대신:

1. **빌드 시**: 루트 `package.json`의 `build` 스크립트에서 runtime을 먼저 IIFE로 빌드하고, 결과물(`packages/runtime/dist/gi-engine.iife.js`)을 `packages/editor/public/runtime/` 에 복사한다.
2. **개발 시**: Vite의 `publicDir`를 통해 `public/runtime/gi-engine.iife.js`가 정적 서빙된다.
3. **PreviewPane**: `fetch('/runtime/gi-engine.iife.js')`로 JS 문자열을 가져와 `srcdoc` 템플릿 리터럴에 인라인한다.

```typescript
// src/hooks/usePreviewSync.ts (srcdoc 생성 핵심)
const buildSrcdoc = (runtimeJs: string, definition: GameDefinition, locale: Locale) => `
<!DOCTYPE html>
<html>
<head>
  <meta charset="UTF-8">
  <style>body { margin: 0; overflow: hidden; }</style>
  <script>
    window.__GI_INITIAL_DEF__ = ${JSON.stringify(definition)};
    window.__GI_LOCALE__ = '${locale}';
  </script>
  <script>${runtimeJs}</script>
</head>
<body>
  <div id="gi-root"></div>
  <script>
    const engine = new GIEngine();
    engine.init(document.getElementById('gi-root'), window.__GI_INITIAL_DEF__, { locale: window.__GI_LOCALE__ });
    window.addEventListener('message', (e) => {
      if (e.data?.type === 'GI_UPDATE_DEFINITION') {
        engine.reload(e.data.definition);
      }
    });
  </script>
</body>
</html>
`;
```

## 11. 아키텍처 결정 요약

| 결정 | 선택 | 대안 검토 | 근거 |
|------|------|-----------|------|
| **단일 Zustand 스토어** | 슬라이스로 분리된 단일 스토어 | 여러 독립 스토어 | GameDefinition이 단일 트리이므로 교차 슬라이스 업데이트가 빈번. 단일 스토어가 일관성 보장 |
| **SVG 기반 캔버스** | SVG overlay + CSS transform scale | HTML5 Canvas API | SVG viewBox가 씬 해상도와 1:1 매핑 → 좌표 변환 단순화. React 트리에서 핫스팟 관리 용이 |
| **iframe PreviewPane** | srcdoc + postMessage | 직접 GIEngine 인스턴스화 | 에디터 React 트리와 런타임 DOM 완전 격리. 런타임 CSS가 에디터를 오염시키지 않음 |
| **인라인 에셋 (base64)** | `AssetDefinition.inline` | 별도 에셋 디렉토리 | 단일 `.gi-project` 파일로 완결. 파일 경로 관리 불필요 |
| **드래그 중 로컬 state** | PointerUp에서만 스토어 커밋 | 매 PointerMove마다 스토어 업데이트 | 불필요한 immer produce 호출 방지 → 60fps 달성 |
| **exporter 브라우저 빌드** | `package.json` exports browser 엔트리 | 에디터 내 exporter 로직 재구현 | DRY 원칙. exporter 로직 단일 유지 |
