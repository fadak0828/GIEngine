## 1. 아키텍처 개요

### 1.1 패키지 의존성 그래프

```
@gi-engine/core (순수 TypeScript, 의존성 0)
       ↑                    ↑
@gi-engine/runtime          @gi-engine/exporter
(DOM 기반 게임 플레이어)     (Node.js CLI 번들러)
       ↑                    ↑
       └────── 런타임을 IIFE로 빌드하여 exporter가 인라인 ──┘
```

### 1.2 계층 구조

```
┌─────────────────────────────────────────┐
│             Exporter (CLI)              │  Phase 3
│  입력: GameDefinition JSON + assets     │
│  출력: 단일 HTML 파일                    │
├─────────────────────────────────────────┤
│           Runtime Engine                │  Phase 2
│  ┌──────┐ ┌──────────┐ ┌────────────┐ │
│  │Scene │ │ DragDrop │ │ Deduction  │ │
│  │Render│ │ Manager  │ │  Render    │ │
│  └──┬───┘ └────┬─────┘ └─────┬──────┘ │
│     │          │              │         │
│  ┌──┴──────────┴──────────────┴──────┐ │
│  │        Engine Controller          │ │
│  │  (이벤트 라우팅, 상태→렌더 동기화)  │ │
│  └───────────────┬───────────────────┘ │
├──────────────────┼──────────────────────┤
│            Core Layer                   │  Phase 1
│  ┌───────────┐ ┌┴──────────┐ ┌───────┐│
│  │  Models   │ │   State   │ │ i18n  ││
│  │ (타입 정의)│ │  Machine  │ │Manager││
│  └───────────┘ └───────────┘ └───────┘│
│  ┌───────────┐ ┌───────────┐          │
│  │ Validator │ │   Save    │          │
│  │  Engine   │ │ Manager   │          │
│  └───────────┘ └───────────┘          │
└─────────────────────────────────────────┘
```

### 1.3 핵심 설계 원칙

| 원칙 | 적용 |
|------|------|
| **순수 함수 우선** | StateMachine, Validator는 부수효과 없는 순수 함수 |
| **단방향 데이터 흐름** | Event → StateMachine → Effects → Renderer |
| **DI 기반 조합** | 모듈 간 인터페이스로 연결, 구현체는 주입 |
| **프레임워크 미사용** | 런타임에 React/Vue 없음. 순수 DOM 조작 |
| **제로 외부 의존성** | core/runtime 패키지는 npm 의존성 0개 |

## 2. 컴포넌트 설계

### 2.1 Core: StateMachine (`packages/core/src/state/`)

```typescript
// state-machine.ts — 게임의 두뇌
export function transition(
  state: GameState,
  save: SaveState,
  event: GameEvent,
  definition: GameDefinition
): StateTransitionResult {
  // 순수 함수: (현재상태, 세이브, 이벤트, 게임정의) → (다음상태, 세이브변경, 부수효과)
}

// 내부 전이 테이블 구조
type TransitionHandler = (
  state: GameState,
  save: SaveState,
  event: GameEvent,
  def: GameDefinition
) => StateTransitionResult | null; // null = 전이 불가

// 전이 테이블: [현재상태 타입, 이벤트 타입] → 핸들러
const TRANSITION_TABLE: Map<string, TransitionHandler>;
```

**설계 결정**: XState 등 라이브러리 대신 직접 구현. 이유:
1. 번들 크기 0 (런타임에 포함되므로 100KB 제한 고려)
2. 전이 테이블 방식으로 테스트 용이
3. 직렬화/역직렬화 자유

### 2.8 Exporter (`packages/exporter/src/`)

```typescript
// cli.ts — CLI 진입점
// $ npx gi-export --input game.json --output game.html --mode production

// bundler.ts — 핵심 번들링 로직
export class Bundler {
  async bundle(options: BundleOptions): Promise<BundleResult> {
    // 1. 게임 정의 로드 및 검증
    const definition = await this.loadAndValidate(options.input);

    // 2. 에셋 수집 및 인라이닝
    const inlinedDef = await this.inlineAssets(definition, options.assetDir);

    // 3. 런타임 JS 빌드 (Vite 라이브러리 모드 → IIFE)
    const runtimeJs = await this.buildRuntime(options.mode);

    // 4. CSS 번들링
    const css = await this.bundleCss();

    // 5. HTML 조립
    const html = this.assembleHtml(inlinedDef, runtimeJs, css, options);

    // 6. 미니파이 (프로덕션)
    if (options.mode === 'production') {
      return this.minify(html);
    }
    return html;
  }
}

// asset-inliner.ts — 에셋 base64 변환
export class AssetInliner {
  async inlineAsset(asset: AssetDefinition, baseDir: string): Promise<string>;
  async optimizeImage(buffer: Buffer, format: string): Promise<Buffer>;
}
```

## 3. 데이터 흐름

### 3.1 메인 게임 루프

```
유저 액션 (클릭/드래그/키보드)
    │
    ▼
InputHandler/DragDropManager
    │ GameEvent 생성
    ▼
Engine.dispatch(event)
    │
    ▼
transition(state, save, event, definition)  ← 순수 함수
    │
    ├─→ nextState: GameState
    ├─→ saveState: Partial<SaveState>
    └─→ effects: SideEffect[]
         │
         ▼
    Engine.executeEffects()
    ├─→ play_sound → AudioManager.play()
    ├─→ save_game → SaveManager.save()
    ├─→ show_popup → Renderer.showPopup()
    └─→ unlock_case → (SaveState 업데이트)
         │
         ▼
    Renderer.render(nextState, updatedSave, definition)
    ├─→ DOM diff (최소 업데이트)
    └─→ 화면 갱신 완료
```

### 3.2 드래그 앤 드롭 흐름

```
pointerdown (워드뱅크 단어)
    │
    ▼ DragDropManager: 드래그 시작
    │ ghost 엘리먼트 생성, pointer capture
    │
pointermove
    │
    ▼ ghost 위치 업데이트
    │ 유효 드롭 타겟 하이라이트
    │
pointerup
    │
    ├─ 슬롯 위? → dispatch(ASSIGN_WORD { slotId, wordId })
    │              → 상태 전이 → 리렌더
    │
    └─ 슬롯 밖? → ghost 제거, 원위치 복원
```

### 3.3 익스포트 흐름

```
CLI 입력 (game.json + assets/)
    │
    ▼
1. Schema Validation (ajv)
    │ ❌ 에러 리포트 + 종료
    ▼ ✅
2. Asset Collection
    │ 파일 시스템에서 에셋 수집
    ▼
3. Asset Optimization
    │ 이미지 리사이즈/WebP, 오디오 압축
    ▼
4. Base64 Inlining
    │ 모든 에셋을 data URI로 변환
    ▼
5. Runtime Build (Vite)
    │ packages/runtime → IIFE 단일 JS
    ▼
6. CSS Bundle
    │ packages/runtime/styles → 단일 CSS
    ▼
7. HTML Assembly
    │ 템플릿에 JS, CSS, GameData 주입
    ▼
8. Minification (prod only)
    │ terser (JS) + cssnano (CSS)
    ▼
Output: game.html
```

## 4. 에러 처리 전략

### 4.1 계층별 에러 처리

| 계층 | 전략 | 예시 |
|------|------|------|
| **Core (StateMachine)** | 무효 전이는 무시 (현재 상태 유지) + 콘솔 경고 | 잠긴 사건 선택 시도 |
| **Core (Validator)** | never throw. 항상 ValidationResult 반환 | 빈 슬롯은 'incorrect' |
| **Core (SaveManager)** | try/catch + 기본값 폴백 | localStorage 꽉 참 → 경고 |
| **Core (i18n)** | 폴백 체인: 현재 → 기본 → 빈 문자열 | 번역 누락 → 기본 언어 |
| **Runtime (Renderer)** | DOM 조작 에러 → 콘솔 에러 + 복구 시도 | 요소 미발견 → 재생성 |
| **Runtime (DragDrop)** | pointer 이벤트 실패 → ghost 정리 + 상태 리셋 | 드래그 중 포커스 이탈 |
| **Runtime (Audio)** | 재생 실패 → 무시 (음소거 상태 유지) | 모바일 자동재생 차단 |
| **Exporter** | 검증 실패 → 상세 에러 메시지 + non-zero exit | 누락 에셋 ID |

## 5. 테스트 전략

### 5.1 테스트 매트릭스

| 패키지 | 테스트 유형 | 도구 | 커버리지 목표 |
|--------|-----------|------|-------------|
| core | 단위 테스트 | Vitest | 90%+ |
| core | 프로퍼티 기반 테스트 | fast-check + Vitest | 상태 머신 |
| runtime | 단위 테스트 | Vitest + happy-dom | 70%+ |
| runtime | 통합 테스트 | Vitest + happy-dom | 주요 플로우 |
| exporter | 단위 테스트 | Vitest | 80%+ |
| exporter | 스냅샷 테스트 | Vitest | HTML 구조 |

### 5.2 핵심 테스트 시나리오

**StateMachine** (20+ 테스트):
- 모든 유효 전이: loading→case_select→exploring→thinking→completed
- 무효 전이 거부: 잠긴 사건 선택, 잘못된 장면 이동
- 부수효과 생성: 사운드, 세이브, 언락
- 경계 조건: 빈 게임, 단일 사건, 모든 퍼즐 완료

**ValidatorEngine** (15+ 테스트):
- 전체 정답 → 모든 슬롯 correct
- 부분 정답 → 해당 슬롯 partial
- 전체 오답 → 모든 슬롯 incorrect
- 혼합 → 정확한 슬롯별 판별
- 빈 슬롯 → incorrect
- 서브 퍼즐 유형별 검증

**DragDropManager** (10+ 테스트):
- 워드→슬롯 드래그 성공
- 슬롯→워드뱅크 반환
- 슬롯→슬롯 이동
- 카테고리 제한 슬롯에 부적합 단어
- 잠긴 슬롯에 드롭 시도

## 7. 성능 고려사항

### 7.1 렌더링 최적화

- **최소 DOM 업데이트**: 상태 변경 시 전체 리렌더가 아닌, 변경된 부분만 업데이트
  - 방법: 이전 상태와 비교하여 변경된 뷰만 교체
  - 씬 전환: 새 씬 DOM 사전 생성 → 교체 (노드 재사용)
- **이미지 프리로딩**: 현재 사건의 모든 씬 배경을 미리 로드
- **CSS 트랜지션 활용**: JavaScript 애니메이션 대신 CSS transition/animation 우선

### 7.2 메모리 관리

- **사건 단위 로딩**: 현재 사건 + 인접 사건만 메모리에 유지
- **에셋 캐시**: 한번 디코딩한 이미지는 Image 객체로 캐시
- **이벤트 리스너 정리**: 씬 전환 시 이전 씬의 리스너 제거

### 7.3 번들 크기 최적화

- **Tree shaking**: Vite의 rollup tree-shaking으로 사용하지 않는 코드 제거
- **에셋 최적화**: exporter에서 이미지 크기 제한 (최대 1920px 폭)
- **코드 분할 없음**: 단일 HTML이므로 코드 분할 불가 → 처음부터 경량 설계

## 8. 확장 포인트

Phase 4-6를 위해 Phase 1-3에서 준비하는 확장 포인트:

| 확장 포인트 | 구현 방식 |

| 플러그인 | `GameSettings.flags` + `SaveState.flags`로 커스텀 데이터 저장 |
| 테마 | CSS 변수 기반 → 게임 데이터에 커스텀 변수 정의 가능 |
