## 1. 제품 개요 및 비전

### 1.1 제품 정의

GIEngine(Golden Idol Engine)은 "The Case of the Golden Idol" 스타일의 추리/추론 게임을 제작하고 배포할 수 있는 게임 엔진이다. 최종 결과물은 **단일 HTML 파일**로 익스포트되어 별도의 서버나 설치 없이 브라우저만으로 플레이 가능하다.

### 1.2 핵심 가치

| 가치 | 설명 |
|------|------|
| **제로 인프라** | 단일 HTML 파일로 완결. 웹 서버, CDN, 백엔드 불필요 |
| **즉시 플레이** | 파일을 열면 바로 게임 시작. 로딩, 설치, 로그인 없음 |
| **완전한 이식성** | 이메일 첨부, USB, 로컬 저장 등 어떤 방식으로든 배포 가능 |
| **다국어 내장** | 한국어/영어 동시 지원. 런타임에서 언어 전환 가능 |

### 1.3 레퍼런스 게임: The Case of the Golden Idol

GIEngine이 구현하는 게임 루프는 다음과 같다:

```
[사건 선택] → [탐색 모드] ⇄ [추리 모드] → [검증] → [다음 사건 잠금 해제]
```

- 플레이어는 사건 현장을 탐색하며 단서(강조된 단어)를 수집한다
- 수집한 단어를 빈칸에 드래그앤드롭하여 사건의 진실을 재구성한다
- 정답 여부에 따라 색상 코드(초록/노랑/빨강)로 피드백을 받는다
- 하나의 사건을 해결하면 다음 사건이 순차적으로 해금된다

### 1.4 Phase 로드맵 개요

| Phase | 범위 | 상태 |
|-------|------|------|
| **Phase 1** | 코어 데이터 모델 + 상태 머신 | 본 사양 대상 |
| **Phase 2** | 브라우저 런타임 엔진 (DOM 기반) | 본 사양 대상 |
| **Phase 3** | 단일 HTML 익스포터 | 본 사양 대상 |

## 3. 핵심 게임 메카닉

### 3.1 게임 구조 계층

```
Game (전체 게임)
├── Act (막, 선택적 그룹핑)
│   ├── Case (사건)
│   │   ├── Scene (장면, 1개 이상)
│   │   │   ├── Hotspot (상호작용 영역)
│   │   │   │   ├── ExamineAction (조사 → 텍스트/이미지 표시)
│   │   │   │   └── WordRevealAction (단어 수집)
│   │   │   └── Layer (시각적 레이어, z-index 기반)
│   │   └── Puzzle (퍼즐, 1개 이상)
│   │       ├── MainPuzzle (메인 추리 퍼즐)
│   │       └── SubPuzzle (서브 퍼즐, 0개 이상)
│   └── ...
└── ...
```

### 3.2 탐색 모드 (Exploring Mode)

#### 3.2.1 장면 탐색

- 각 사건은 1개 이상의 **장면(Scene)**으로 구성된다
- 장면은 배경 이미지 위에 여러 **핫스팟(Hotspot)**이 배치된 포인트앤클릭 화면이다
- 장면 간 이동은 네비게이션 핫스팟(문, 화살표 등)을 통해 수행된다
- 장면은 다중 레이어를 가질 수 있다 (예: 서랍 열기 → 내부 레이어 표시)

#### 3.2.2 핫스팟 상호작용

핫스팟은 플레이어가 클릭할 수 있는 영역으로, 다음 동작을 트리거한다:

| 동작 유형 | 설명 | 예시 |
|-----------|------|------|
| `examine` | 텍스트 팝업 표시 | 편지 내용 읽기, NPC 대사 |
| `examine_image` | 이미지 팝업 표시 | 문서 확대, 그림 상세 |
| `word_reveal` | 단어 수집 + 강조 표시 | "독약", "2층", "존 스미스" |
| `navigate` | 다른 장면으로 이동 | 방 이동, 층 이동 |
| `toggle_layer` | 레이어 표시/숨김 | 서랍 열기, 커튼 젖히기 |
| `composite` | 여러 동작 순차 실행 | 조사 후 단어 자동 수집 |

#### 3.2.3 단어 수집 시스템

- 핫스팟에서 발견한 **강조 단어(highlighted word)**는 자동으로 **워드 뱅크**에 추가된다
- 워드 뱅크는 사건 단위로 관리된다 (사건별 독립 워드 뱅크)
- 이미 수집한 단어는 탐색 시 시각적으로 구분된다 (밑줄, 색상 변경 등)
- 단어에는 **카테고리**가 있을 수 있다 (인물명, 장소, 도구, 행위 등)

### 3.3 추리 모드 (Thinking/Deduction Mode)

#### 3.3.1 퍼즐 구조

각 사건에는 1개의 **메인 퍼즐**과 0개 이상의 **서브 퍼즐**이 있다.

**메인 퍼즐**: 사건의 핵심 진실을 재구성하는 빈칸 채우기
- 예: "[___]이(가) [___]에서 [___]을(를) 사용하여 [___]을(를) 살해했다"

**서브 퍼즐**: 사건의 세부 사항을 확인하는 보조 퍼즐
- **인물 식별(Character ID)**: 초상화와 이름을 매칭
- **시나리오 퍼즐**: 특정 상황에 대한 추론 (동기, 알리바이 등)
- **타임라인 퍼즐**: 사건의 시간순 재구성
- **관계도 퍼즐**: 인물 간 관계 매핑

#### 3.3.2 드래그 앤 드롭 인터랙션

```
[워드 뱅크]                    [빈칸 문장]
┌─────────────────────┐        ┌──────────────────────────────┐
│ 독약  존  2층  칼    │  ──→  │ [___]이 [___]에서 [___]을    │
│ 메리  서재  밧줄     │  드래그 │ 사용하여 피해자를 공격했다     │
└─────────────────────┘        └──────────────────────────────┘
```

- 워드 뱅크에서 단어를 드래그하여 빈칸 슬롯에 드롭한다
- 하나의 슬롯에는 하나의 단어만 배치할 수 있다
- 이미 배치된 단어를 다른 슬롯으로 이동하거나, 워드 뱅크로 되돌릴 수 있다
- 슬롯은 허용하는 단어 카테고리를 제한할 수 있다 (선택적)
- 터치 디바이스에서도 동일하게 동작해야 한다 (터치 드래그)

#### 3.3.3 검증 및 피드백 시스템

플레이어가 "확인" 버튼을 누르면 다음 로직이 실행된다:

| 상태 | 색상 | 조건 | 시각 효과 |
|------|------|------|-----------|
| **정답** | 초록 (`#4CAF50`) | 해당 슬롯의 단어가 정확히 일치 | 슬롯 배경 초록, 잠금 |
| **부분 정답** | 노랑 (`#FFC107`) | 올바른 카테고리이나 정확한 단어가 아님 | 슬롯 배경 노랑 |
| **오답** | 빨강 (`#F44336`) | 완전히 틀림 | 슬롯 배경 빨강, 흔들림 애니메이션 |

**검증 규칙**:
- 검증은 **퍼즐 단위**로 수행된다 (슬롯 개별 검증이 아님)
- 모든 슬롯이 초록이면 퍼즐 완료로 처리한다
- 완료된 퍼즐의 슬롯은 잠금 처리되어 변경할 수 없다
- 검증 횟수에 제한은 없다 (무제한 시도)
- 메인 퍼즐이 완료되어야 다음 사건이 해금된다
- 서브 퍼즐은 선택적이며, 메인 퍼즐 완료와 독립적이다

### 3.4 사건 진행 시스템

#### 3.4.1 순차 해금 (Sequential Unlock)

```
Case 1 [해금] → Case 2 [잠금] → Case 3 [잠금] → ... → Case N [잠금]
        ↓ 완료
Case 1 [완료] → Case 2 [해금] → Case 3 [잠금] → ... → Case N [잠금]
```

- 게임 시작 시 첫 번째 사건만 해금 상태이다
- 사건의 **메인 퍼즐**을 완료하면 다음 사건이 해금된다
- 완료한 사건은 언제든 재방문하여 서브 퍼즐을 풀 수 있다
- `Act` 단위 그룹핑은 시각적 구분 용도이며, 해금 로직에 영향을 주지 않는다

#### 3.4.2 세이브/로드

- 게임 진행 상황은 `localStorage`에 자동 저장된다
- 저장 데이터: 해금된 사건 목록, 수집한 단어, 퍼즐 상태, 현재 위치
- 수동 저장/불러오기는 Phase 1-3에서 제공하지 않는다 (자동 저장만)
- `localStorage` 키는 게임 ID 기반으로 네임스페이스를 구분한다

## 4. 데이터 모델

### 4.1 게임 정의 (Game Definition)

게임 데이터는 JSON 형식으로 작성되며, 엔진이 이를 로드하여 실행한다.

```typescript
/** 게임 전체를 정의하는 최상위 구조 */
interface GameDefinition {
  /** 게임 고유 식별자. localStorage 네임스페이스 등에 사용 */
  id: string;

  /** 게임 버전. 세이브 데이터 호환성 체크에 사용 */
  version: string;

  /** 게임 제목. i18n 키 또는 LocalizedText */
  title: LocalizedText;

  /** 게임 설명 */
  description: LocalizedText;

  /** 지원 언어 목록. 첫 번째가 기본 언어 */
  supportedLocales: Locale[];

  /** 게임 설정 */
  settings: GameSettings;

  /** 막(Act) 목록. Act 없이 cases 직접 나열도 가능 */
  acts: Act[];

  /** 전역 에셋 정의 */
  assets: AssetManifest;
}

/** 지원 로케일 */
type Locale = 'ko' | 'en';

/** 다국어 텍스트. 모든 사용자 노출 텍스트에 사용 */
interface LocalizedText {
  ko: string;
  en: string;
}

/** 게임 전역 설정 */
interface GameSettings {
  /** 검증 시 색상 피드백 표시 시간(ms). 기본값: 2000 */
  validationFeedbackDuration: number;

  /** 자동 저장 간격(ms). 0이면 비활성화. 기본값: 5000 */
  autoSaveInterval: number;

  /** 디버그 모드 활성화. 프로덕션 빌드에서는 무시 */
  debug: boolean;

  /** 사건 해금 방식 */
  unlockMode: 'sequential' | 'all_unlocked';

  /** 커스텀 CSS 클래스 프리픽스. 충돌 방지용 */
  cssPrefix: string;
}
```

### 4.2 사건 구조 (Act, Case)

```typescript
/** 막 - 사건의 시각적 그룹 */
interface Act {
  id: string;
  title: LocalizedText;
  cases: Case[];
}

/** 사건 - 게임의 핵심 단위 */
interface Case {
  id: string;
  title: LocalizedText;
  description: LocalizedText;

  /** 사건의 장면 목록. 첫 번째가 시작 장면 */
  scenes: Scene[];

  /** 사건의 퍼즐 정의 */
  puzzles: PuzzleSet;

  /** 이 사건 해금에 필요한 선행 사건 ID 목록 */
  prerequisites: string[];

  /** 사건 선택 화면 썸네일 */
  thumbnail: AssetRef;
}
```

### 4.3 장면 및 핫스팟 (Scene, Hotspot)

```typescript
/** 장면 - 탐색 가능한 하나의 화면 */
interface Scene {
  id: string;
  name: LocalizedText;

  /** 배경 이미지 */
  background: AssetRef;

  /** 장면의 기본 크기(px). 핫스팟 좌표의 기준 */
  dimensions: { width: number; height: number };

  /** 핫스팟 목록 */
  hotspots: Hotspot[];

  /** 시각적 레이어 목록 */
  layers: SceneLayer[];

  /** 장면 진입 시 실행할 동작 */
  onEnter?: ActionSequence;

  /** BGM 또는 앰비언스 */
  audio?: AssetRef;
}

/** 시각적 레이어 */
interface SceneLayer {
  id: string;

  /** 레이어 이미지 */
  image: AssetRef;

  /** 레이어 위치 (장면 좌표 기준) */
  position: Position;

  /** z-index. 높을수록 위에 표시 */
  zIndex: number;

  /** 초기 표시 여부. 기본값: true */
  visible: boolean;
}

/** 핫스팟 - 상호작용 가능 영역 */
interface Hotspot {
  id: string;

  /** 핫스팟 영역 정의 */
  area: HotspotArea;

  /** 클릭 시 실행할 동작 */
  action: HotspotAction;

  /** 마우스 오버 시 커서 스타일. 기본값: 'pointer' */
  cursor: string;

  /** 이 핫스팟이 활성화되기 위한 조건. 없으면 항상 활성 */
  condition?: VisibilityCondition;

  /** 접근성: 핫스팟 설명 */
  ariaLabel: LocalizedText;
}

/** 핫스팟 영역 형태 */
type HotspotArea =
  | { type: 'rect'; x: number; y: number; width: number; height: number }
  | { type: 'circle'; cx: number; cy: number; radius: number }
  | { type: 'polygon'; points: [number, number][] };

/** 표시 조건 */
type VisibilityCondition =
  | { type: 'layer_visible'; layerId: string }
  | { type: 'word_collected'; wordId: string }
  | { type: 'puzzle_solved'; puzzleId: string }
  | { type: 'and'; conditions: VisibilityCondition[] }
  | { type: 'or'; conditions: VisibilityCondition[] }
  | { type: 'not'; condition: VisibilityCondition };
```

### 4.4 핫스팟 동작 (Actions)

```typescript
/** 핫스팟 동작 유형 */
type HotspotAction =
  | ExamineAction
  | ExamineImageAction
  | WordRevealAction
  | NavigateAction
  | ToggleLayerAction
  | CompositeAction;

/** 텍스트 팝업 표시 */
interface ExamineAction {
  type: 'examine';

  /** 표시할 텍스트 내용 */
  content: LocalizedText;

  /** 팝업 제목 (선택적) */
  title?: LocalizedText;

  /** 텍스트 내에서 강조할 단어 ID 목록. 클릭 시 수집 가능 */
  highlightedWords?: string[];
}

/** 이미지 팝업 표시 */
interface ExamineImageAction {
  type: 'examine_image';
  image: AssetRef;
```

### 6.2 모듈 책임

| 모듈 | 책임 | 의존성 |
|------|------|--------|
| **StateMachine** | 게임 상태 관리, 전이 규칙 실행, 이벤트 디스패치 | 없음 (순수) |
| **Renderer** | DOM 요소 생성/업데이트, CSS 클래스 토글, 애니메이션 | StateMachine |
| **InputHandler** | 마우스/터치 이벤트 캡처, 핫스팟 히트 테스트 | Renderer |
| **DragDropManager** | 드래그앤드롭 상태 관리, 터치 대응, 드롭 영역 감지 | InputHandler, Renderer |
| **SaveManager** | localStorage 읽기/쓰기, 직렬화/역직렬화, 버전 마이그레이션 | StateMachine |
| **AssetLoader** | base64 디코딩, 이미지/오디오 프리로딩, 로딩 진행률 | 없음 |

| **AudioManager** | BGM/효과음 재생, 볼륨 제어, 음소거 | AssetLoader |
| **ValidatorEngine** | 퍼즐 정답 검증, 부분 정답 판별, 결과 생성 | 없음 (순수) |

#### 6.3.2 CSS 요구사항

- 모든 스타일은 엔진 루트(`.gi-engine`) 아래에 스코핑된다
- CSS 변수를 사용하여 테마 커스터마이징을 지원한다
- 반응형 디자인: 최소 320px ~ 최대 1920px 뷰포트 지원
- 검증 색상은 CSS 변수로 정의한다:

```css
  --gi-color-partial: #FFC107;
```

#### 6.3.3 장면 렌더링

- 장면은 **상대 좌표 시스템**을 사용한다 (0-100% 또는 장면 dimensions 기준)
- 핫스팟 영역은 SVG 또는 투명 div로 렌더링한다
- 장면 크기는 뷰포트에 맞게 비율 유지하며 스케일링한다 (`contain` 방식)
- 레이어는 absolute positioning + z-index로 겹쳐 표시한다

#### 6.3.4 드래그 앤 드롭

- HTML5 Drag and Drop API를 기본으로 사용한다
- 터치 디바이스 대응: `touchstart`, `touchmove`, `touchend` 이벤트 폴백
- 드래그 중인 단어는 고스트 이미지로 표시한다
- 유효한 드롭 영역은 시각적으로 강조한다 (테두리, 배경색)
- 슬롯에 드롭 시 스냅 애니메이션을 적용한다
- 키보드 대안: 단어 선택(Enter) → 슬롯 선택(화살표 + Enter) 패턴

### 6.4 오디오 요구사항

- BGM: 장면별 루프 재생, 장면 전환 시 크로스페이드
- 효과음: 단어 수집, 드래그, 드롭, 검증 결과 (정답/오답)
- 음소거 토글: 전역 음소거 버튼, 상태 localStorage 저장
- 모바일: 사용자 인터랙션 후에만 오디오 컨텍스트 활성화

### 6.5 접근성 요구사항

- 모든 핫스팟에 `aria-label` 제공
- 키보드 네비게이션: Tab으로 핫스팟 이동, Enter로 상호작용
- 스크린 리더 대응: `role`, `aria-live`, `aria-describedby` 적용
- 색상 대비: WCAG 2.1 AA 기준 충족 (4.5:1 이상)
- 드래그 앤 드롭의 키보드 대안 제공

## 7. 단일 HTML 익스포트 요구사항

### 7.1 익스포트 파이프라인

```
GameDefinition (JSON)
      │
      ▼
┌─────────────┐    ┌─────────────┐    ┌──────────────┐
│  Validate   │───►│   Bundle    │───►│   Optimize   │
│  Schema     │    │   Assets    │    │   Output     │
└─────────────┘    └─────────────┘    └──────┬───────┘
                                             │
                                             ▼
                                     single.html
```

### 7.2 번들링 전략

**목표**: 모든 게임 리소스를 단일 `.html` 파일에 포함한다.

| 리소스 유형 | 인라인 방식 |
|-------------|-------------|
| JavaScript | `<script>` 태그 내 번들링된 코드 |
| CSS | `<style>` 태그 내 전체 스타일시트 |
| 이미지 | base64 data URI (`data:image/png;base64,...`) |
| 오디오 | base64 data URI (`data:audio/mp3;base64,...`) |
| 폰트 | base64 data URI (`@font-face { src: url(data:...) }`) |
| 게임 데이터 | `<script type="application/json" id="gi-game-data">` |

### 7.3 HTML 구조

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title><!-- 게임 제목 --></title>
  <style>
    /* 전체 CSS (엔진 + 게임 커스텀) */
  </style>
</head>
<body>
  <div id="gi-engine-root"></div>

  <!-- 게임 데이터 (JSON) -->
  <script type="application/json" id="gi-game-data">
    { /* GameDefinition with inlined assets */ }
  </script>

  <!-- 엔진 런타임 (번들링된 JS) -->
  <script>
    // GIEngine runtime code
    // 즉시 실행: 게임 데이터 로드 → 에셋 준비 → 게임 시작
  </script>
</body>
</html>
```

### 7.4 익스포터 기능 요구사항

| 기능 | 설명 |
|------|------|
| **스키마 검증** | GameDefinition JSON의 구조적 유효성 검증 |
| **에셋 인라이닝** | 모든 외부 파일을 base64로 변환하여 인라인 |
| **코드 번들링** | 엔진 TypeScript → 단일 JS 번들 (Vite rollup) |
| **CSS 번들링** | 모든 CSS를 단일 `<style>` 블록으로 병합 |
| **크기 리포트** | 익스포트 결과의 크기 분석 보고 (전체, JS, CSS, 에셋별) |
| **무결성 검사** | 참조된 에셋 ID가 모두 존재하는지 확인 |
| **미니파이** | JS/CSS 미니파이 (프로덕션 빌드) |
| **소스맵 옵션** | 디버그 빌드 시 인라인 소스맵 포함 |

### 7.5 빌드 명령

```bash
# 개발 빌드 (소스맵 포함, 미니파이 없음)
npm run export -- --input game.json --output game.html --mode development

# 프로덕션 빌드 (미니파이, 소스맵 없음)
npm run export -- --input game.json --output game.html --mode production

# 크기 분석 포함
npm run export -- --input game.json --output game.html --analyze
```

## 8. 국제화(i18n) 요구사항

```typescript
function resolveText(text: LocalizedText, locale: Locale, fallback: Locale): string;
```

## 부록

### A. 용어 사전

| 용어 | 정의 |
|------|------|
| Act (막) | 사건의 시각적 그룹. 게임 진행에는 영향 없음 |
| Case (사건) | 게임의 핵심 단위. 탐색 + 퍼즐로 구성 |
| Scene (장면) | 하나의 탐색 가능한 화면 |
| Hotspot | 장면 내 상호작용 가능한 영역 |
| Layer | 장면 위에 겹치는 시각적 레이어 |
| Word (단어) | 수집 가능한 텍스트 조각. 퍼즐의 답안 후보 |
| Word Bank (워드 뱅크) | 수집한 단어의 목록 |
| Slot (슬롯) | 퍼즐 빈칸. 단어를 배치하는 대상 |
| Puzzle (퍼즐) | 수집한 단어로 풀어야 하는 추리 문제 |
| Validation (검증) | 퍼즐 정답 확인 프로세스 |
| Export (익스포트) | 게임 데이터 + 엔진을 단일 HTML로 번들링 |

### B. 기술 스택 상세

| 항목 | 선택 | 사유 |
|------|------|------|
| 언어 | TypeScript 5.x (strict) | 타입 안전성, 인터페이스 기반 설계 |
| 빌드 도구 | Vite 6 | 빠른 HMR, Rollup 기반 프로덕션 빌드 |
| 패키지 관리 | npm workspaces | 모노레포 구조 (engine / exporter / sample-games) |
| 테스트 | Vitest | Vite 네이티브, TypeScript 지원 |
| 런타임 UI | Pure DOM + CSS | 프레임워크 의존성 제거, 번들 최소화 |
| 상태 관리 | 커스텀 상태 머신 | 외부 라이브러리 없이 순수 구현 |
| 린팅 | ESLint + Prettier | 코드 품질 + 포맷 일관성 |
