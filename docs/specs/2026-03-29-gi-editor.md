## 1. 제품 개요 및 목표

### 1.1 제품 정의

GIEngine Visual Editor는 게임 디자이너가 JSON을 직접 작성하지 않고도 GIEngine 게임을 제작할 수 있는 웹 기반 GUI 도구이다. 브라우저에서 직접 실행되며, 별도의 서버 없이 로컬 파일 시스템과 상호작용한다.

### 1.2 핵심 가치

| 가치 | 설명 |
|------|------|
| **코드 없는 게임 제작** | JSON 문법 없이 비주얼 인터페이스만으로 완성된 게임 제작 |
| **즉시 피드백** | 라이브 프리뷰 패널에서 실시간으로 게임 상태 확인 |
| **완전한 i18n** | 모든 에디터 UI와 게임 콘텐츠가 한국어/영어 동시 입력 지원 |
| **원클릭 익스포트** | 작업 중인 게임을 즉시 단일 HTML 파일로 출력 |
| **GIEngine 타입 완전 호환** | 에디터 출력은 `packages/core`의 `GameDefinition` 스키마와 100% 호환 |

### 1.3 Phase 4 목표

Phase 4는 에디터 MVP(Minimum Viable Product)를 제공한다. 목표는 숙련된 게임 디자이너가 JSON 없이 다음을 달성하는 것이다:

1. 새 프로젝트를 생성하고 `.gi-project` 파일로 저장/불러오기
2. 막(Act)과 사건(Case)을 시각적으로 구성
3. 배경 이미지 위에 핫스팟을 배치하고 동작을 지정
4. 빈칸 채우기 퍼즐 템플릿 설계 및 정답 정의
5. 에셋(이미지, 오디오) 업로드 및 관리
6. 워드 뱅크 단어 생성 및 편집
7. 단일 HTML 파일로 익스포트

## 2. 대상 사용자 (페르소나)

### 2.1 게임 디자이너 (비기술 사용자)

| 항목 | 내용 |
|------|------|
| **배경** | 스토리텔링, 퍼즐 설계, 아트 방향 전문가. 프로그래밍 경험 최소 |
| **목표** | 아이디어를 플레이 가능한 게임으로 빠르게 구현 |
| **주요 작업** | 장면 편집, 핫스팟 배치, 퍼즐 설계, 텍스트 입력 |
| **불편 요소** | JSON 문법 오류, 에셋 경로 관리, 데이터 구조 암기 |
| **성공 지표** | JSON을 열지 않고도 완성된 게임 파일 생성 |

### 2.2 기술 개발자 (프로젝트 검증자)

| 항목 | 내용 |
|------|------|
| **배경** | TypeScript/JavaScript 숙련. GIEngine 패키지를 직접 사용 가능 |
| **목표** | 에디터를 통해 복잡한 데이터 구조를 빠르게 프로토타이핑 |
| **주요 작업** | 에디터 출력 검증, 고급 조건식 설정, 에셋 최적화 |
| **불편 요소** | GUI와 실제 JSON 불일치, 검증 없는 저장 |
| **성공 지표** | 에디터 출력이 `GameDefinition` 스키마 100% 준수 |

## 3. 기능 목록 및 수락 기준

### F-01: 프로젝트 관리

**설명**: 새 프로젝트 생성, `.gi-project` 파일 저장/불러오기, 프로젝트 메타데이터 편집.

**수락 기준**:
- 새 프로젝트 생성 시 기본 `GameDefinition` 골격(빈 acts, 기본 settings)이 생성된다
- 프로젝트를 `.gi-project` JSON 파일로 저장할 수 있다 (File System Access API 또는 다운로드)
- 저장된 `.gi-project` 파일을 불러올 수 있다
- 프로젝트 제목(ko/en), 설명(ko/en), ID, 버전을 편집할 수 있다
- 저장되지 않은 변경사항이 있을 때 브라우저 이탈 시 경고를 표시한다

### F-02: 막(Act) 및 사건(Case) 관리자

**설명**: `acts` 배열과 각 Act 내의 `cases` 배열을 시각적으로 편집.

**수락 기준**:
- 막(Act)을 추가, 이름 편집(ko/en), 삭제, 순서 변경(드래그 앤 드롭)할 수 있다
- 막 안에 사건(Case)을 추가, 이름 편집(ko/en), 설명 편집(ko/en), 삭제, 순서 변경할 수 있다
- 사건의 thumbnail AssetRef를 에셋 라이브러리에서 선택할 수 있다
- 사건의 prerequisites(선행 사건 ID 목록)를 편집할 수 있다
- 막/사건 목록은 트리 구조로 표시된다

### F-03: 비주얼 씬 에디터

**설명**: 배경 이미지 위에 핫스팟을 배치, 크기 조정, 삭제하는 캔버스 기반 에디터.

**수락 기준**:
- 씬의 배경 이미지를 에셋 라이브러리에서 선택할 수 있다
- 배경 이미지 위에 rect 타입 핫스팟을 마우스 드래그로 생성할 수 있다
- 기존 핫스팟을 드래그로 이동, 핸들로 크기 조정할 수 있다
- 핫스팟을 선택하면 우측 패널에서 속성(action, condition, ariaLabel ko/en, cursor)을 편집할 수 있다
- 핫스팟 action 타입을 선택할 수 있다: `examine`, `examine_image`, `word_reveal`, `navigate`, `toggle_layer`, `composite`
- 각 action 타입별 필드를 입력 폼으로 편집할 수 있다
- 씬 목록(같은 사건의 다른 씬들)을 패널에서 관리할 수 있다 (추가, 삭제, 이름 변경)
- `SceneLayer`를 추가, 이미지 지정, 위치/z-index 편집, 삭제할 수 있다
- 씬의 audio AssetRef를 에셋 라이브러리에서 선택할 수 있다
- 씬 캔버스는 에디터 내 고정 뷰포트에 맞게 비율을 유지하며 스케일된다

### F-04: 퍼즐 디자이너

**설명**: `PuzzleSet`(main + sub)을 시각적으로 설계.

**수락 기준**:
- 메인 퍼즐의 제목(ko/en), 설명(ko/en)을 편집할 수 있다
- 퍼즐 템플릿을 WYSIWYG 방식으로 구성할 수 있다: `text` 세그먼트 입력, `slot` 삽입 버튼, `line_break` 삽입 버튼
- 각 `slot` 세그먼트에 대해 slotId, placeholder(ko/en), acceptCategory를 설정할 수 있다
- 각 slot에 대한 `AnswerDefinition`(correctWordId, partiallyCorrectWordIds)을 워드 뱅크에서 선택하여 지정할 수 있다
- 서브 퍼즐을 추가할 수 있다: `character_id`, `timeline`, `scenario`, `relationship` 중 선택
- `character_id` 서브 퍼즐: 캐릭터 슬롯(portrait, nameSlotId, answerId)을 편집할 수 있다
- `timeline` 서브 퍼즐: 타임라인 슬롯(slotId, label ko/en, answerId)을 편집할 수 있다
- `scenario` 서브 퍼즐: 메인 퍼즐과 동일한 템플릿 편집 인터페이스를 사용한다
- `relationship` 서브 퍼즐: 노드(id, label, portrait)와 엣지(fromNodeId, toNodeId, slotId, answerId)를 편집할 수 있다
- `minWordsRequired` 값을 숫자 입력으로 설정할 수 있다

### F-05: 에셋 라이브러리

**설명**: 이미지 및 오디오 파일을 업로드, 미리보기, 관리.

**수락 기준**:
- 이미지(PNG, JPG, WebP, SVG) 파일을 업로드할 수 있다
- 오디오(MP3, OGG, WAV) 파일을 업로드할 수 있다
- 업로드된 에셋은 썸네일 그리드로 표시된다
- 에셋을 클릭하면 미리보기(이미지: 확대, 오디오: 재생)가 표시된다
- 에셋의 id, alt(ko/en)를 편집할 수 있다
- 에셋을 삭제할 수 있다 (참조 중인 에셋 삭제 시 경고)
- 에셋 데이터는 프로젝트 파일 내 `AssetManifest`에 base64로 인라인 저장된다
- 에셋 라이브러리 패널에서 검색(id 기준)할 수 있다

### F-06: 워드 뱅크 에디터

**설명**: 게임 전체에서 사용할 `Word` 목록을 생성, 편집.

**수락 기준**:
- 새 단어를 추가할 수 있다: id, display(ko/en), category, caseId 입력
- 기존 단어를 편집, 삭제할 수 있다
- 단어를 category, caseId로 필터링할 수 있다
- id는 중복 불가이며 중복 시 인라인 오류를 표시한다
- `WordCategory` 값(`person`, `place`, `object`, `action`, `time`, `motive`, `evidence`, 커스텀)을 드롭다운으로 선택할 수 있다

### F-07: 라이브 프리뷰 패널

**설명**: 현재 편집 중인 사건을 `packages/runtime` 엔진으로 실시간 렌더링하여 미리보기.

**수락 기준**:
- 에디터 우측 또는 하단에 분리 가능한 프리뷰 패널이 있다
- 프리뷰 패널은 현재 선택된 사건의 현재 씬을 렌더링한다
- 에디터에서 데이터가 변경될 때 프리뷰가 자동으로 갱신된다 (debounce 500ms)
- 프리뷰 내에서 핫스팟을 클릭하여 실제 게임처럼 인터랙션을 테스트할 수 있다
- 프리뷰 패널의 로케일(ko/en)을 독립적으로 전환할 수 있다
- 프리뷰 패널 크기를 조절할 수 있다 (리사이즈 핸들)

### F-08: 익스포트

**설명**: `packages/exporter`를 호출하여 단일 HTML 파일 생성.

**수락 기준**:
- "Export" 버튼 클릭 시 현재 프로젝트를 단일 HTML 파일로 브라우저 다운로드한다
- 익스포트 전 `GameDefinition` 스키마 검증을 수행하고, 오류 목록을 표시한다
- 검증 오류가 있을 경우 익스포트를 중단하고 오류 위치(어느 사건/씬/퍼즐)를 명시한다
- 익스포트 진행 중 로딩 인디케이터를 표시한다
- 익스포트된 HTML 파일은 Phase 3 exporter와 동일한 품질의 단일 HTML이어야 한다

### F-09: 게임 설정 편집기

**설명**: `GameSettings` 오브젝트 필드를 편집.

**수락 기준**:
- `validationFeedbackDuration` (ms, 숫자 입력)을 편집할 수 있다
- `autoSaveInterval` (ms, 숫자 입력)을 편집할 수 있다
- `debug` 플래그(체크박스)를 편집할 수 있다
- `unlockMode` (`sequential` | `all_unlocked`, 드롭다운)를 편집할 수 있다
- `cssPrefix` (문자열 입력)를 편집할 수 있다

## 5. 데이터 흐름: 에디터 상태 → GameDefinition

### 5.1 에디터 스토어 구조

에디터는 Zustand 스토어 하나에 모든 상태를 관리한다. 스토어의 핵심 슬라이스는 다음과 같다:

```typescript
interface EditorStore {
  // 프로젝트 메타
  projectMeta: {
    filePath: string | null;      // 현재 저장 경로
    isDirty: boolean;             // 미저장 변경 여부
    lastSavedAt: Date | null;
  };

  // 핵심 게임 데이터 (GameDefinition과 1:1 대응)
  definition: GameDefinition;

  // 에디터 UI 상태 (GameDefinition에 포함되지 않음)
  selection: {
    actId: string | null;
    caseId: string | null;
    sceneId: string | null;
    hotspotId: string | null;
    puzzleId: string | null;
  };
  activePanel: 'scene' | 'puzzle' | 'assets' | 'words' | 'settings';
  previewLocale: Locale;
  previewVisible: boolean;

  // 액션
  updateDefinition: (patch: DeepPartial<GameDefinition>) => void;
  setSelection: (selection: Partial<EditorStore['selection']>) => void;
  // ... 개별 CRUD 액션
}
```

### 5.2 GameDefinition 생성 경로

```
에디터 상태 변경
    │
    ▼
Zustand 스토어 업데이트 (immer 기반 불변 업데이트)
    │
    ├──→ React 컴포넌트 리렌더 (선택적 구독)
    │
    └──→ previewSync (debounce 500ms)
              │
              ▼
         definition 객체를 JSON 직렬화
              │
              ▼
         iframe postMessage → 런타임 엔진 재초기화
              │
              ▼
         라이브 프리뷰 갱신
```

### 5.3 저장/불러오기 흐름

```
저장:
definition (EditorStore) → JSON.stringify() → .gi-project 파일 다운로드
                                               (또는 File System Access API write)

불러오기:
.gi-project 파일 선택 → JSON.parse() → 스키마 검증 → EditorStore 초기화
```

### 5.4 익스포트 흐름

```
Export 버튼 클릭
    │
    ▼
스키마 검증 (core의 validator 사용)
    │
    ├── 오류 있음 → 오류 목록 모달 표시 (중단)
    │
    └── 오류 없음 → exporter.bundle(definition) 호출
                        │
                        ▼
                   단일 HTML 생성 → 브라우저 다운로드
```

### 5.5 핫스팟 캔버스 → GameDefinition 매핑

캔버스의 핫스팟 좌표는 실제 씬 `dimensions`에 대한 **비율 좌표**로 저장된다. 이는 에디터 뷰포트 크기와 무관하게 동일한 결과를 보장한다.

```
캔버스 드래그 이벤트 (픽셀 좌표)
    │
    ▼
픽셀 좌표 ÷ 캔버스 표시 크기 × 씬 dimensions
    │
    ▼
HotspotArea { type: 'rect', x, y, width, height } (씬 원본 해상도 기준)
    │
    ▼
definition.acts[i].cases[j].scenes[k].hotspots[l].area 업데이트
```

## 7. i18n 요구사항

### 7.1 두 가지 i18n 레이어

Phase 4 에디터에는 두 가지 독립적인 i18n 레이어가 존재한다.

| 레이어 | 설명 | 관리 위치 |
|--------|------|-----------|
| **에디터 UI i18n** | 에디터 자체의 버튼, 라벨, 메시지 텍스트 | `packages/editor/src/i18n/` |
| **게임 콘텐츠 i18n** | GameDefinition 내 `LocalizedText` 필드 | `GameDefinition` 스키마 (core 타입) |

### 7.2 에디터 UI i18n

- 에디터 인터페이스는 한국어(ko)와 영어(en)를 지원한다
- 기본 언어는 브라우저 언어 설정을 따른다 (fallback: ko)
- Header의 언어 토글로 전환 가능
- 에디터 UI 번역은 `packages/editor/src/i18n/` 폴더의 `ko.json`, `en.json`으로 관리
- `packages/core`의 `I18nManager`를 에디터 UI에도 재사용한다

### 7.3 게임 콘텐츠 i18n

- `LocalizedText` 타입(`{ ko: string; en: string }`)을 받는 모든 입력 필드는 **ko/en 탭을 가진 이중 입력 컴포넌트**(`LocalizedTextInput`)로 표현된다
- 두 언어 모두 입력이 가능하며, 한쪽만 입력해도 저장은 가능하되 빈 언어에 대한 경고를 표시한다
- 프리뷰 패널의 로케일을 독립적으로 전환하여 각 언어의 결과를 확인할 수 있다

### 7.4 LocalizedTextInput 컴포넌트 명세

```
┌───────────────────────────────────┐
│  [KO] [EN]                        │  ← 언어 탭
│  ┌─────────────────────────────┐  │
│  │ (한국어 텍스트 입력)         │  │
│  └─────────────────────────────┘  │
└───────────────────────────────────┘
```

- Props: `value: LocalizedText`, `onChange: (v: LocalizedText) => void`, `label?: string`, `multiline?: boolean`
- 활성 탭의 텍스트 영역만 표시 (토글 전환)
- 비어 있는 언어 탭에 경고 배지(⚠) 표시

## 8. 패키지 통합 포인트

### 8.1 `@gi-engine/core` 의존성

| 사용 항목 | 에디터에서의 용도 |
|-----------|------------------|
| `GameDefinition`, 모든 타입 | 스토어의 핵심 데이터 타입으로 직접 사용 |
| `LocalizedText`, `Locale` | 모든 i18n 입력 컴포넌트의 타입 |
| `I18nManager` | 에디터 UI 텍스트 렌더링에 재사용 |
| `validatePuzzle` | 익스포트 전 퍼즐 검증 |
| `getAllCases`, `findCase`, `findScene` | 트리 및 씬 참조 헬퍼 |
| `createInitialSaveState` | 프리뷰 패널 초기 세이브 상태 생성 |

### 8.2 `@gi-engine/runtime` 의존성

- 에디터는 라이브 프리뷰를 위해 `@gi-engine/runtime`의 `GIEngine` 클래스를 `<iframe>` 내에서 인스턴스화한다
- iframe은 `packages/runtime`을 IIFE 번들로 빌드하여 `srcdoc`으로 주입한다
- 에디터 ↔ 프리뷰 iframe 통신은 `postMessage`를 통해 `GameDefinition` JSON을 전달한다

```
에디터 컨텍스트                    iframe 컨텍스트
──────────────                    ──────────────
definition 변경
    │
    ▼
postMessage({                  →  GIEngine.init(definition)
  type: 'UPDATE_DEFINITION',       또는
  definition: ...               GIEngine.reload(definition)
})
```

### 8.3 `@gi-engine/exporter` 의존성

- 에디터의 "Export" 기능은 `@gi-engine/exporter`의 `Bundler` 클래스를 직접 호출한다
- 브라우저 환경에서 동작하므로, exporter는 Node.js fs 모듈 없이 `Blob` API 기반으로 동작하는 **브라우저 호환 번들러** 인터페이스가 필요하다
- exporter 패키지는 `browser` 빌드 엔트리를 추가하여 이를 지원해야 한다 (또는 에디터가 exporter 로직의 브라우저 서브셋을 직접 구현)

### 8.4 패키지 의존성 그래프 (Phase 4 포함)

```
@gi-engine/core (의존성 0)
       ↑                    ↑                    ↑
@gi-engine/runtime    @gi-engine/exporter   @gi-engine/editor
(DOM 런타임)          (번들러)              (React 에디터)
       ↑                    ↑
       └──────────── @gi-engine/editor (두 패키지 모두 소비)
```

## 10. 수락 기준 (번호 목록)

다음 기준이 모두 충족되어야 Phase 4가 완료된 것으로 간주한다.

### 프로젝트 관리

1. 새 프로젝트를 생성하면 유효한 빈 `GameDefinition` 골격이 Zustand 스토어에 초기화된다.
2. "저장" 버튼 클릭 시 현재 `definition`이 `.gi-project` 확장자로 JSON 다운로드된다.
3. ".gi-project 파일 열기"로 기존 파일을 불러오면 스토어가 해당 `definition`으로 교체된다.
4. 저장되지 않은 변경사항이 있을 때 페이지를 닫거나 새로고침하면 브라우저 `beforeunload` 경고가 표시된다.

### 사건 관리

5. 막(Act)을 추가/삭제/이름 변경/순서 변경하면 스토어의 `definition.acts` 배열이 즉시 반영된다.
6. 사건(Case)을 추가/삭제/이름 변경/설명 변경하면 해당 Act의 `cases` 배열이 즉시 반영된다.
7. 사건의 prerequisites를 편집하면 `case.prerequisites` 배열이 정확히 업데이트된다.

### 씬 에디터

8. 씬에 배경 이미지를 설정하면 캔버스에 해당 이미지가 표시된다.
9. 캔버스에서 마우스 드래그로 rect 핫스팟을 그릴 수 있으며, 생성된 핫스팟이 `scene.hotspots`에 추가된다.
10. 기존 핫스팟을 드래그로 이동하거나 핸들로 크기를 조정하면 `hotspot.area` 좌표가 씬 원본 해상도 기준으로 업데이트된다.
11. 핫스팟을 선택하면 오른쪽 패널에서 action 타입을 변경할 수 있으며, 각 타입에 맞는 입력 폼이 표시된다.
12. `examine` action의 content(ko/en), title(ko/en), highlightedWords 배열을 편집할 수 있다.
13. `word_reveal` action의 wordIds 목록을 워드 뱅크에서 선택하여 편집할 수 있다.
14. `navigate` action의 targetSceneId를 현재 사건의 씬 목록에서 선택할 수 있다.
15. `toggle_layer` action의 layerId를 현재 씬의 레이어 목록에서 선택할 수 있다.
16. 핫스팟의 ariaLabel(ko/en)을 `LocalizedTextInput`으로 편집할 수 있다.
17. 핫스팟에 `VisibilityCondition`을 설정할 수 있다 (단순 조건 1단계 지원).

### 퍼즐 디자이너

18. 메인 퍼즐 템플릿에 text 세그먼트, slot 세그먼트, line_break 세그먼트를 추가/삭제/순서 변경할 수 있다.
19. 각 slot에 대해 slotId, placeholder(ko/en), acceptCategory를 편집할 수 있다.
20. 각 slot의 정답(correctWordId)을 워드 뱅크에서 선택하여 지정할 수 있다.
21. 부분 정답(partiallyCorrectWordIds)을 복수 선택할 수 있다.
22. `character_id` 서브 퍼즐을 추가하고 캐릭터 슬롯을 편집할 수 있다.
23. `timeline` 서브 퍼즐을 추가하고 타임라인 슬롯을 편집할 수 있다.

### 에셋 라이브러리

24. 이미지(PNG, JPG, WebP, SVG)와 오디오(MP3, OGG, WAV) 파일을 업로드하면 `definition.assets.items`에 추가된다.
25. 업로드된 이미지는 썸네일 그리드에 표시된다.
26. 이미지 클릭 시 원본 크기 미리보기가 표시된다.
27. 오디오 항목 클릭 시 인라인 오디오 플레이어가 표시된다.
28. 에셋의 alt 텍스트(ko/en)를 편집할 수 있다.
29. 에셋 삭제 시 해당 에셋을 참조하는 씬/핫스팟 목록이 경고로 표시된다.

### 워드 뱅크

30. 새 단어를 추가하면 `definition`에 별도로 관리되는 `words` 배열에 추가된다.
31. 단어의 id, display(ko/en), category, caseId를 편집할 수 있다.
32. 중복 id 입력 시 폼에 즉각적인 오류 메시지가 표시된다.
33. category 및 caseId 필터를 적용하면 해당 조건의 단어만 목록에 표시된다.

### 라이브 프리뷰

34. 에디터에서 데이터를 변경하면 500ms 디바운스 후 프리뷰 패널이 자동으로 갱신된다.
35. 프리뷰 패널에서 핫스팟을 클릭하면 실제 게임 엔진의 인터랙션이 동작한다.
36. 프리뷰 로케일을 KO/EN으로 전환하면 런타임이 해당 언어로 표시된다.
37. 프리뷰 패널을 접거나 펼칠 수 있다.

### 익스포트

38. "Export" 버튼 클릭 시 `GameDefinition` 스키마 검증이 수행된다.
39. 검증 오류가 있을 경우 오류 항목과 위치(Act/Case/Scene/Puzzle)를 목록으로 표시하고 익스포트가 중단된다.
40. 검증 통과 시 단일 HTML 파일이 브라우저 다운로드로 저장된다.
41. 다운로드된 HTML 파일을 브라우저에서 직접 열면 게임이 정상적으로 플레이된다.

### 게임 설정

42. `GameSettings`의 모든 필드(validationFeedbackDuration, autoSaveInterval, debug, unlockMode, cssPrefix)를 편집 UI에서 변경하면 스토어에 즉시 반영된다.

### 비기능 요구사항

43. 에디터 초기 로딩 시간은 3초 이내(개발 환경 제외)이다.
44. 100개 핫스팟이 있는 씬에서 핫스팟 이동 조작이 버벅임 없이 동작한다 (60fps 목표).
45. 에디터 UI의 모든 인터랙티브 요소는 키보드로 접근 가능하다 (Tab 이동, Enter 활성화).
46. 에디터 UI는 한국어(ko)와 영어(en)로 전환 가능하며, 모든 UI 텍스트가 번역된다.
47. Chrome 최신 버전, Firefox 최신 버전, Edge 최신 버전에서 동작한다.
